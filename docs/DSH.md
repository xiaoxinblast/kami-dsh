# DSH 本地翻译工作台

`kami-dsh` 是 `xiaoxinblast/kami` 的独立衍生项目，保留上游 Git 历史。目标语向为日语→简体中文。

## 安装

当前验证目标为 DSH `0.2.1-rc.5`，同时兼容 `0.2.1-rc.2`、`0.2.1-rc.3` 和 `0.2.1-rc.4`；运行环境使用 DSH 安装包自带的 Electron / Node.js。

1. 在 DSH 的“插件”→“添加插件”中填写 `https://github.com/xiaoxinblast/kami-dsh#main`，安装仓库中的当前版本。依赖由插件管理器安装。
2. 开发时也可在仓库运行 `npm ci`、`npm run dsh:check` 后安装绝对目录；Creator 模式的 `plugin_manager` 使用 `action: install_bundle` 与同一安装地址。
3. 打开一个 DSH 工作区会话，选择“Kami 翻译工作台”预设。工作台自动显示在该会话的右侧标签页，左侧不再提供全局工作台入口。先明确绑定已有 Kami 项目或新建项目。
4. 在主会话中委托翻译，或在右侧“任务”中使用“快捷建批”指定工作区相对路径。面板不再提供第二个聊天输入框。切换会话时，面板、工作区绑定和编辑状态随各自会话隔离。其他预设不显示 Kami 工作台，文件、浏览器、终端标签页继续保留。关闭工作台后，可用会话标题栏或新会话预设旁的双语折页按钮重新打开。
5. 更新预设后新建翻译会话，以使用新版工具组合。

插件只通过 DSH 的管理入口安装，不修改 `app.asar`。更新已加载的 Host 模块后，按插件管理结果处理需要的重启；不要把“依赖已保存”当作已经生效。

本次桌面验收发现，连续热卸载／安装后，表格解析曾报 `ExcelJS.Workbook is not a constructor`；正常退出并重启 DSH 后，同一文件解析成功。更新到 0.9.0 后请正常重启一次 DSH，再开始翻译任务。

GitHub 安装不是自动更新。可通过插件管理页重新安装仓库地址，或使用下述官方 CLI 更新；按管理结果正常重启以加载新模块。本地资产位于独立的数据目录，卸载程序包不删除资产。也可安装明确的发布标签，把运行版本固定到已验收的提交。更新程序包不会把本地数据库或上传文件放进 GitHub。

已使用官方 CLI 注册的 GitHub 程序包也可执行 `dsh plugin --profile desktop update kami-dsh --latest`，然后正常重启桌面端加载新模块。不要手动修改 profile 的清单或安装目录。

若插件页热卸载报告 `profile reload requires the root Include entry`，退出 DSH 后可通过它自带的 CLI 更新程序包。已注册 `dsh` 命令时运行以下命令，再启动桌面端；未注册时可调用安装目录下的 `resources/runtime/cli/bin/dsh.cmd`：

```powershell
dsh plugin --profile desktop remove kami-dsh
dsh plugin --profile desktop add 'github:xiaoxinblast/kami-dsh#main'
```

## 本地数据

数据位于 `$DSH_HOME/kami-dsh/<profile>/`，默认桌面 profile 为 `desktop`。

- `kami.sqlite`：项目、术语、TM、QA、风格、参考资料和学习记录。
- `uploads/`：旧版已导入原文件与参考资料，保留兼容读取；新流程不再复制原件到此目录。
- `runtime/`：参数设置、日志，以及工作区资源解析缓存和任务原件快照，不保存模型 API Key。
- `learning/`：配对评测检查点。
- `exports/`：旧版导出和兼容接口的派生文件；新流程导出到工作区。
- `backups/`：从工作台创建的数据库备份。

数据库备份使用 SQLite 在线备份接口；迁移和完整人工备份还需保留 `uploads/`、`learning/` 与 `runtime/`（含任务原件快照和设置）。恢复应在插件停用时进行，使用备份数据库替换 `kami.sqlite`，同时恢复对应文件目录。

正常工作不启动 Kami HTTP 服务，不连接 Directus，也不依赖 Docker。业务入口在 DSH Host 内执行，SQLite 是正式存储。旧仓库的 HTTP 路由被复用为进程内操作分发，以保留现有翻译、QA、学习与导出行为。

## 一次性迁移

仅迁移时需要旧 Directus 临时可用。先关闭旧工作台的写入操作，再运行：

```powershell
npm run migrate:local -- --source-env '<旧项目>\directus\.env' --source-data '<旧运行目录>\data' --source-data '<旧源码目录>\data'
```

可用 `--destination '<目标数据目录>'` 指定独立目录。工具仅读取旧后台，不更改旧记录；会逐集合读取两遍并比较内容哈希，校验引用文件和数据库完整性后才发布正式数据库。重复执行仅接受与源数据完全相同的目标库，已有不同内容会拒绝覆盖。

结果写入本地 `migration-report.json`。`status: verified` 才表示完成；缺文件、冲突、权限不足或源数据变化均使迁移失败。账号凭据和旧分享链接不迁入。

## 翻译闭环

工作区文件是来源，SQLite 继续保存术语、TM、学习记录和任务。DSH agent 查找文件、选择资源和推进机检，Kami 执行批量翻译、QA、续跑与原格式导出。人工审校在 memoQ 完成；用户关联本地双语人工终稿后，更新 TM、学习差异和术语。学习版本仍需人工激活。

人工终稿达到设置中的候选阈值后，系统自动生成候选；选材优先预留 20 条独立终稿用于配对评测，训练原文及重复原文不能重复计入评测。样本不足时，学习中心显示缺口，后续终稿补齐后自动开始。评测通过后自动运行已启用的固定质量资产门禁；两者均通过时进入“等待确认启用”，不会自动替换生效版本。

评测逐组保存检查点和模型选择，Host 重启后自动续跑有效任务。执行失败的样本最多自动补跑一次，成功样本不重跑；质量未通过时停止推进。重复关联同一终稿不会重复生成候选或评测。自动学习只在 DSH Host 运行期间执行，关闭 Host 期间不运行模型。

### 工作区配置与文件引用

首次使用必须明确绑定项目，不按文件夹名称猜测。`.kami/project.json` 示例：

```json
{
  "version": 1,
  "projectId": "已有或明确新建的 Kami 项目 ID",
  "styleGuides": ["rules/style.md"],
  "terms": ["glossary.xlsx"],
  "translationMemories": ["resources/tm.xlsx"],
  "references": ["references/story.docx"],
  "outputDirectory": "outputs"
}
```

路径均相对当前工作区，不要求移动文件。会话中切换工作目录后，使用 DSH `workingDirectory` 的当前值；目录缺失、越界路径、外部链接均报错，不回退到创建会话时的目录。页面和 agent 共用 Host 文件服务，文件字节不经浏览器或聊天 Base64。

在“资产”页统一管理术语库、记忆库 TM、风格指南和参考资料。术语/TM 进入具体库后，通过“关联文件”填写工作区相对路径，按目录浏览、搜索或查看文件版本；“已有条目”保留库内历史记录。关联不按上传文件的大小或扩展名拦截，不改写原件或自动导入正式条目；“让 Agent 查看原文件”由当前会话使用 DSH 工具查阅。解除关联只修改配置，不删除原件。术语、TM 和风格指南的版本核对使用分块读取计算 SHA-256；参考资料只记录文件服务版本，不扫描原件内容。

术语、TM 和风格指南关联后，界面自动把编译任务交给当前会话的 Agent；工具关联或批量配置返回 `compilation.status: pending` 时，Agent 同样立即继续编译。已有文件可在列表中勾选文件或文件夹，用“全选筛选结果”跨页选择后点击“编译选中”；资产页的“编译全部待编译”覆盖所有启用库及项目风格指南。一次批量操作只提交一个 Agent 任务，先按库检查状态，跳过未变化来源，并显示读取失败的文件。

关联文件名旁显示“已完成编译”或“待编译”气泡。文件夹统计所有层级的关联子文件，全部完成时显示“已完成编译”，否则显示“有文件待编译”，并附已完成数/总数。读取失败显示“状态检查失败”，不计为完成。列表随工作台刷新批量检查当前库；原文件哈希按文件服务版本复用，库覆盖信息按统一编译文件版本复用，未变化时不反复读取原件或解析整库句对。原件变化后重新核验哈希，气泡恢复待编译。

每个术语库、TM 库各保存唯一的统一编译文件；同一项目的风格指南也汇总成一份。选中部分文件时只更新这些来源的贡献，保留未选中内容。Agent 先查阅原件，识别实际列含义、备注、说明行、规则和例外，再全量整理所选来源；可用脚本执行已识别的结构，不要求用户改成固定排版。读取失败或语义不明确时须报告具体问题。风格指南保留完整权威规则、例外和正反例。

每库的本次增量更新数据只写到一份工作区 `.kami/compiled/` JSON，使用 `kami_workspace {action:'compilations',selection:[{path,purpose,libraryId}]}` 返回的该库 `updatePath`。省略 `selection` 检查全部启用资源。每个来源携带当前相对路径和 SHA-256：

```json
{
  "resources": [
    {
      "path": "glossary.xlsx",
      "hash": "该来源当前的 SHA-256",
      "terms": [{ "ja": "設定", "zh": "设置", "note": "界面选项" }]
    }
  ]
}
```

TM 的每个来源使用 `entries:[{source,target,context,file}]`；风格指南使用 `style_guide` 字符串。Agent 再以该组第一个来源调用 `kami_file_import {path:'原文件路径',purpose:'terms|tm|style-guide',libraryId:'所属库',compiledPath:'该库 updatePath'}`；风格指南省略 `libraryId`。Host 验证所有来源属于同一库且版本一致，一次替换所选来源的旧贡献，再合并到该库的唯一编译文件。兼容旧的单源 `source:{path,hash}` 格式，但结果同样进入库文件。原文列、译文列中的表头、空行和 memoQ 保护行会过滤；普通同文句对不会仅因原译文相同而被删掉。大表通过本地更新 JSON 传递，不在聊天或工具参数中反复携带全量句对。

相同术语或句对合并来源和备注；不同译法、TM 上下文、条目身份及约束分别保留，不只按原文覆盖。风格指南只合并完全相同的正文，不做语义删减。合并使用索引，不逐条扫描全库查重；状态检查每库只读取一次汇总文件。每库的增量写入串行合并并原子替换，避免并发更新相互覆盖。

当前来源返回 `compilation.status: ready` 才表示该来源编译完成；结果含有效条数或字符数、库去重数和唯一 `compiledFile` 路径。界面可刷新状态或重试。统一文件位于数据目录的 `runtime/compiled-resources/`，按工作区、项目、用途和所属库隔离，各来源记录自己的哈希，重启后可复用；原件变化只使该来源的旧贡献失效。旧版逐文件缓存会在首次检查或更新时迁入，未变化的有效缓存无需重新交给 Agent 处理。建批自动使用当前版本的有效贡献，术语和 TM 按当前原文检索，风格文本进入模型上下文。编译不增加正式资产库条目，也不改变人工批准状态；旧批次仍使用冻结快照。

术语/TM 的文件归属记录在 `.kami/project.json` 的 `libraryFiles:[{path,purpose,libraryId}]`，`purpose` 为 `terms` 或 `tm`。库列表用 ↑ / ↓ 调整优先级，数字越小越优先；新任务使用所属库当前的优先级和启停状态，已有批次保留冻结的文件库信息。旧版只有路径数组的关联继续可读，按已有相应用途库归属显示，不自动导入库内条目。人工正式术语与批准 TM 的保护规则继续生效。

小型术语、TM 或风格指南也可把完整编译结果传入关联原文件时的 `kami_file_import.resourceContext`：`[{path,hash,text}]`；术语/TM 使用 `pairs:[{source,target,note}]`，同样保存为可复用编译结果。建批时提供的这些资源的 `resourceContext` 则只作为本批临时查阅结果，不覆盖已缓存编译。`hash` 来自同一原文件的资源信息，版本变化后会拒绝旧结果。未提供查阅结果及编译缓存时，Kami 保留对已有结构化术语、TM 和风格格式的内部解析以兼容旧关联。有关联资源时，快捷建批和独立审校默认交给 Agent；待译文件的分段和原格式写回仍使用 Kami 的 TXT、Markdown、DOCX、XLSX、CSV、XLIFF、MQXLIFF 处理链路。

参考资料只关联本地原件。关联和建批只检查路径、大小和文件服务版本，不读取正文或扫描全文哈希，不分块、不建立检索索引，也不要求预先传入 `resourceContext`。翻译或审校模型需要查证设定、人物或用词时，通过 `list_reference_files` 取得原件路径，再调用当前 DSH 会话中已启用的 `read`、`read_image`、`grep`、`glob` 等原生查阅工具；复杂文档可按需加载 Office 技能和依赖，用原生 Bash/PowerShell 只读查阅。调用经过同一 Agent 的 DSH 工具注册表、权限守卫和取消信号，不提供 Kami 写入或委派工具。工具返回的文字、图片直接进入本次模型上下文；读取失败如实报告，不退回旧解析缓存。批次只记录关联时的参考路径和文件服务版本，正文以实际查阅的当前原件为准；无需提前转换全部资料。旧批次中已有的参考解析内容保留存档，后续在 DSH 执行查阅时同样优先读取原件。

DSH 的本地文件及进程内操作不沿用服务器上传大小、请求体大小或 2,000 段限制。原上游 HTTP 服务的兼容接口仍保留自己的上传规则，DSH 日常操作不经过这些上传入口。

“解析并创建批次”就是任务创建边界：此时读取原文及术语、TM、风格指南的最新版，记录相对路径、SHA-256、解析快照，并在本地 `runtime/workspace-snapshots/` 保存用于格式写回的待译原件快照。后续运行、暂停、续跑、重启后续跑和导出使用该快照；原文及上述资源修改后需创建新批次。参考资料仅记录路径与版本信息，翻译时由 Agent 按需读取当前原件，不建立新的正文解析缓存。

工作区指南只用于任务，不启用或改写项目级旧指南。文件术语不覆盖主库已有术语；文件 TM 作为当前任务的未批准参考，不能充当人工批准的 QA 规范。引用文件不会重复写入术语、TM 或参考资料主库。旧项目指南、旧任务和 `uploads/` 继续可读，不自动迁移或清理。

导出默认写入工作区 `outputs/`，可指定工作区内的完整相对文件路径，例如 `outputs/dialogue.zh-CN.docx`。输出采用排他创建；同名文件报错，既有文件和源文件均不覆盖。DSH 文件服务当前只提供文本写入，二进制导出在 Host 校验同一服务解析的目标路径后使用本地排他创建。

### Agent 示例

先明确绑定项目，然后可以直接委托：

> 用 `rules/style.md` 和 `glossary.xlsx` 翻译 `source/dialogue.docx`，结果放到 `outputs/`。

- `kami_workspace`：`status` 查询；`bind` 指定已有 `projectId` 或明确新建的 `name`；`configure` 设置上述资源路径和输出目录。
- `kami_file_import`：`{path,purpose}`，用途为 `translation`（默认）、`style-guide`、`terms`、`tm`、`reference`。术语/TM 可指定当前项目的 `libraryId` 关联到具体库。原有 `{path,projectId}` 参数保留，项目必须与工作区绑定一致。`register:false` 只核查原文件信息；创建待译批次时可用 `resources` 覆盖本次资源路径数组，并以 `resourceContext` 提供 Agent 实际查阅结果。
- `kami_workbench`：按批次 ID 启动、暂停、QA、检查进度与导出。`POST /api/batch/export` 可带 `outputPath`，返回工作区文件路径。
- `kami_help`：操作索引与当前工作区状态。

批次模型审校调用 `POST /api/auto-qa` 时携带 `batchId`、`projectId`、`locale`、`source` 和 `translation`，使用该批次冻结的指南和术语等资源；不存在的批次报错，不回退到当前文件。省略 `batchId` 则是独立审校，读取当前工作区的最新资源。

模型优先使用关联会话待生效的模型选择，其次是最近一次请求的 provider/model，新会话使用 DSH 默认模型。所有调用经过 DSH 模型服务，不另存模型 Key。固定 seed 不可用会明确标记，截断、错误和取消会转为失败，不能算作成功译文。Agent 按已配置工具的能力查阅原文件；Kami 内部的图片识别通过 DSH 附件协议保存和发送图片，需要关联会话所选模型支持图像输入，不支持时如实报告失败。

工具和页面调用相同业务操作。页面通过独立的 DSH Remote 调用，不向关联会话追加命令或 JSON 记录；当前会话提供工作目录和模型选择，匹配 Kami 预设后接收明确发送的 agent 任务。批准、正式采纳、激活和删除保留为用户操作。大结果分页读取；导出文件返回本地路径，不把二进制塞进模型上下文。手动执行 `/kami` 仍保留 DSH 的命令日志。

专用预设包含 `@deepseek-ai/dsh-tool-fs` 与 `@deepseek-ai/dsh-tool-fs-search`，保留 DSH 通用工具，不再统一过滤。翻译业务通过 Kami 工具执行，文件查找、读取和编辑使用原生 DSH 工具。批次翻译与 QA 的内部调用也在进程内分发，不回调本机 HTTP 端口。

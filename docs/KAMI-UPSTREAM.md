# Kami 本地化工作台

面向日语源文到简体中文的 AI 本地化工作台。Directus + PostgreSQL 提供日中语言资产后台，不以英文为中间语言。

## 已实现

- Directus 11.17.4 + PostgreSQL 资产后台、表格管理、筛选、审批和修改记录
- 日语→简体中文术语表、翻译记忆与 API 检索入口
- 宣发、公告、道具名、道具描述、UI、规则、对白、社媒等自动语体识别
- 精确、别名、模糊匹配，以及领域/语体/批准状态加权
- `.xlsx` / `.csv` 日中表格上传，自动识别日语列及简体中文目标列
- `.xliff` / `.mqxliff`（XLIFF 1.2）批次导入与原位写回，保护既有目标、锁定单元和内联标签
- 术语表拖入后立即执行 AI 结构识别；无表头、前置说明行和元数据列不再阻断上传，AI 不可用时回退整列规则推断
- 短对照自动进入术语候选，完整日中句段自动分流到简体中文翻译记忆和风格证据
- 规则去噪、重复合并、现有术语检查、译法冲突提示与可选 AI 二次清洗
- 导入批次、候选判断依据、原表行号和人工采用结果完整留存在 Directus
- OpenAI-compatible 模型服务，兼容本地 Ollama/LM Studio/vLLM 或云端服务
- 按日语→简体中文与项目生成版本化风格规范（语体/领域只作分层取样与排序的标签），翻译任务固定记录实际使用版本
- 翻译前检索同语言相似译例（语体/领域只作排序加权，不再过滤）；翻译后执行硬 QA + 结构化 AIQA，由后端按问题严重度计算百分制分数
- 独立 Auto QA 页面：粘贴原文与译文即可做逐句质检——先按句切分并自动对齐（语义向量优先，Embedding 不可用时由模型逐句对齐，支持拆句/并句合并，可标出整句漏译/增译），再对每一句分层独立审查：语言正确性专项（拼写/语法/标点，模型）与品牌名/格式/一致性（本地规则）计入基本检查维度、语义忠实性（着重检查项，critical 封顶 65 分）、nuance 一致性（对照风格规范、已批准译例与历史风格证据）；综合分按 20 / 50 / 30 加权，模型不可用时自动只跑本地基本检查层；每次质检自动存为任务中心里的 Auto QA 报告，可回放不重烧模型
- 批次分享验证页：翻译批次与 Auto QA 报告均可一键生成分享链接（局域网免登录访问，token 即权限），创建即时返回；同事在独立分享页查看每段的日语原文、简体中文译文、QA 评分与问题，Auto QA 分享还带文档级三维评分、对齐说明与整句级漏译/增译；同事可逐段提出要求（可附建议译法），反馈进入任务中心的待采纳队列，采纳后写入风格证据池（满 8 条且通过蒸馏闸门时自动生成风格草稿），忽略则仅留档
- 右上角反馈铃铛：自动轮询（15 秒）分享页收到的同事反馈，新反馈到达时弹出提醒并显示未处理角标；点开铃铛集中展示全部待批准反馈（原文、当前译文、要求与建议译法），逐条"批准入风格"（写入风格证据池）或忽略，无需到任务中心逐个翻找
- 后台任务中心：术语导入（识别清洗与入库全程进度可见、历史批次可回看）、双语资产导入（后台分库写入，关掉页面也会跑完，中断后可直接续跑）、Embedding 重建（后台执行，探针发现外部向量服务不可用时自动改用本地词面向量）与批次导出（后台合并生成 Excel，完成后一键下载，刷新页面不丢失）统一进入任务中心"后台任务"类型，进行中显示进度、失败显示原因、可删除
- AIQA 低于 90 分自动最小修订并重新盲审，最多两轮；通过后沉淀机器验证译例，问题译文进入独立 QA 案例库
- 参数设置面板：把原本写死在代码或环境变量里的调优参数集中到界面（页头「参数设置」），改动即时生效无需重启。覆盖 QA 通过分与修订轮数、Auto QA 三维权重与各级扣分、参考译例与 QA 反例条数、上下文段数、风格蒸馏与自动提议的阈值与增长窗口、评测最小样本，以及简体中文的作品名括号约定。每项都有区间校验：越界夹紧、三维权重之和必须为 100（否则整组回落）、增长窗口不得大于阈值（否则功能被配死），被自动校正的项会逐条列出而不是悄悄改掉输入。已有环境变量（`KAMI_STYLE_DISTILL_*` / `KAMI_AUTO_PROPOSE_*`）仍然优先，面板会标注并置灰。技能策略与面板的优先级：技能里的值仍等于出厂值说明学习循环没动过它，听面板；已偏离出厂值说明是评测晋升的结果，尊重技能
- 审校证据分权威等级：只有人工批准的译例（人工采纳、表格导入）会作为"已批准译例"提交给审校模型；本系统自己 QA 通过后写回的机器译文单独列为 machineDrafts，仅用于发现同一文档内自相矛盾，提示词明确禁止拿它当正误依据。否则一次错误会在下一次审校里升格为规范
- Auto QA 分数按段平均而非全文累加：每段独立计分后取平均，坏掉一段只影响 1/段数；阻断问题在段级压到 60/65，文档级封顶 65，另有 `blockedSegments` 计数区分"坏一段"与"全坏"
- 简体中文标点约定进入本地硬检查：日语的 `「」`、`『』` 混入译文、作品名括号不符合《》约定都会被指出（`src/orthography.mjs`），同时把约定注入翻译提示词，从源头减少照搬。
- 数字按**数值等价**校验而非字面包含：日语日期、金额和数量按简体中文习惯改写不再判成漏掉受保护内容；只有数字确实无法从译文还原时提示复核。带单位的数值（50%、100元）仍要求原样保留
- 语体与领域**全自动判定、只作参考**：语体由整份文件的语境分析与逐段特征判定，领域按语体与正文关键词推断、最后回落通用；界面上不再有语体/领域选择器，判定结果只影响提示词、质量档与检索排序
- **语体/领域不再过滤检索**：记忆、QA 案例不再按语体/领域收窄候选，同语体同领域只作为排序加成（`SCOPE_RANK_BONUS` ≤6%）；语体判错或领域选错都不会让参考译例归零
- **大库检索走候选池**：TM 有 8 万条时，"整库取回逐条算编辑距离"每段要 11–17 秒、要传几百 MB。`src/memory-index.mjs` 用字符 n-gram 倒排 + IDF 先把整库收窄成 top-K 候选（默认 1000，见设置项「TM 候选池大小」，0 = 不粗筛），再交给原有打分函数精排——打分公式、相似度门槛、范围加成一律不变。三条硬规则：完全相同的原文无条件进候选；查询凑不出 n-gram（如「設定」两个字）时退回子串包含匹配；任何 TM 写入都会让索引失效并重建（8.3 万行重建约 2 秒，选候选约 7 毫秒）。实测 top-1/top-5 与整库打分完全一致，单段从 16 秒降到 0.25 秒
- 语体与领域的判定结果当场可见：翻译页实时显示「语体 宣发文案（表格声明）· 领域 市场营销（语体决定）· 置信度 92%」，不必等翻译跑完；Auto QA 报告的对照证据里同样列出
- 语体分类优先读需求表自己声明的用途：`位置` / `描述` 等列命中关键词时直接采用（视频标题→宣发、导航栏文本→UI、FAQ→通用），比从正文猜测可靠；无描述时回落原有启发式
- fidelity 维度按**信息点**判定：先从日语原文列出可核实的信息点（事实、数字、日期、名称、平台、条件、否定、承诺强度），再逐个检查能否从简体中文译文还原；助词、敬体语尾、主语省略、句子拆合与语气词改写一律不算漏译增译
- 可选 Embedding 模型（如 nomic-embed-text）启用语义向量检索：记忆与 QA 案例写入时自动向量化，检索混合词面相似度与余弦打分；未配置时自动回退词面检索。**风格证据不再写入向量**——证据池按"人工采纳优先 → 语体分层 → 来源覆盖"取样读取（`src/evidence-sample.mjs`），不做向量检索；将来要做语义取样先跑一次「Embedding 重建」回填即可
- 单句与批量译文均可人工编辑后“采纳为正式译法”：写入人工批准记忆与风格证据，同句旧机器译文自动降权
- 任务后复盘：批量翻译完成后自动复盘 QA 轨迹与人工采纳证据，跨批次累计风格证据达阈值后蒸馏新的风格规范草稿，并蒸馏日语→简体中文译者画像（翻译时始终注入）
- 风格蒸馏闸门：同一作用域内只要还有待审核的风格草稿就不再生成新草稿；上一版蒸馏之后，证据池必须再新增满一个增长窗口（默认 8 条）才会重新蒸馏。复盘产出的增量补丁走同一道闸门，因此一个作用域在任何时刻最多只有一个待审草稿，界面会显示本次跳过的具体原因（阈值未到 / 有待审草稿 / 增量不足）
- **规则级累积**：风格规范不再是每轮重写的散文，而是带稳定 id 的规则集。蒸馏产出的是对已有规则的增量操作（keep / update / add / retire），本轮没提到的规则**不会消失**——只有连续多轮（默认 4 轮，可调）没被证据确认才退休，且退休写明原因、记录保留可复核。每条规则累计它历轮的证据数，长期成立的规则权重越来越高。这是"素材越多风格越准"成立的前提：旧实现每轮只看最近 N 条重写整份规范，第 10 条证据学到的规则会随窗口滚出去而静默消失，实测同一个作用域 481 条证据能产出 181 到 1466 字不等的规范，差别只来自抽到哪 30 条
- 风格规范只有一个写入口：任务后复盘保留问题趋势分析，但不再自己写 profile——那条旁路会绕过规则累积，把刚攒起来的规则一次性抹平成散文
- 蒸馏取样上限可调（默认正例 50 条 / 反例 15 条）：50 条约 3k 字符、200 条约 13k，对现代模型都不是上下文压力，真正的上限是样本太多时模型倾向给泛泛总结而非锐利规则
- 改动式风格学习：人工采纳时同时留存被替换掉的机器初稿，蒸馏时模型看到的是 `原文 / 机器初稿 / 人工定稿` 三元组——**人改了什么**才是风格信号，只看定稿无法区分改的是语气、长度还是称谓。原样采纳与表格导入的对照分别标为 confirmed / imported，权重更低
- 风格反例入池：同事在分享页只提出问题、没有给出改写时，被否决的正是当前译文，这条译文按反例（negative）入库并保留否决理由，绝不会当作正例喂给模型；译者画像与 Auto QA 的参考证据都只取正例
- 风格草稿配对评测：草稿可与当前生效版本在人工终稿留出集上做配对评测，唯一变量就是风格规范本身（技能、留出集、检索隔离两侧完全一致）。AIQA 始终以**当前生效版本**为尺子给两边打分，避免草稿用自己的标准给自己评分；因此 QA 分只作回归护栏，晋升理由只认与人工终稿的编辑距离、强制术语与硬错误。评测结论反对时激活会被拦下，确需启用必须显式忽略结论，该决定连同依据一起记录在规范上
- 风格规范与译者画像采用人工闸门：AI 蒸馏产物一律进入草稿，在术语库页对比新旧差异后激活才参与翻译
- 批量翻译进度保存在服务端（JSON 文件或 Directus batch_runs），刷新页面后自动恢复
- 译文中实际采用的正式术语以红色虚线标记，悬停可查看中外术语对照
- 近似、错字和字符重排命中只作为智能候选；译文对应表达以蓝色虚线标记，可点击确认并原位替换为正式译法
- 单句翻译与批次 / 文件翻译双模式；支持粘贴长文以及 `.txt`、`.md`、`.docx`、`.xlsx`
- 文件按结构、换行和完整句子自动分段，逐段携带相邻上下文执行翻译、术语检查和 QA
- Excel 拖入后先由 AI 识别表头行及正文、位置/备注、DDL/字数/语种约束、已有译文等列角色；无表头时根据列分布和内容样本自动推断
- Excel 只把正文列生成翻译单元，同一行的补充信息、约束和已有译文作为 Context Pack 输入，不会被误当正文翻译
- 批次可暂停续跑、跳过分段、编辑译文、重试失败项，并合并导出为原文件格式
- 收敛为翻译、Auto QA、术语导入、术语库等页面；页面主操作统一位于页头

## 运行

要求 Node.js 20 或更高版本、Docker Desktop 和 Docker Compose。首次运行：

```powershell
npm run directus:up
npm run directus:provision
npm start
```

然后打开：

- Kami 工作台：`http://127.0.0.1:4173`
- Directus 资产后台：`http://127.0.0.1:18055/admin/content/terms_zh_cn`

管理员邮箱和密码保存在本机 `directus/.env`，该文件已加入 `.gitignore`。Kami 服务端使用单独的最小权限 Service Token，不向浏览器暴露管理员令牌。

常用管理命令：

```powershell
npm run directus:up
npm run directus:down
npm run directus:provision
npm run directus:snapshot
```

`directus:provision` 是幂等的，可以安全地重新检查缺失集合、字段、权限和种子数据。Schema 快照保存在 `directus/schema/snapshot.yaml`。

**升级提示**：改动式风格学习与风格评测新增了 `style_evidence.machine_translation` / `polarity` / `note` 与 `style_profiles.evaluation` 字段。Directus 模式下需要重新执行 `npm run directus:provision`；未执行时这些字段写入会失败，历史证据按正例回落，不影响既有翻译流程。

**升级提示（双语资产导入）**：术语候选新增 `term_candidates.note` 字段（原表注释），后台任务新增 `asset_import` 类型。Directus 模式下同样需要重新执行 `npm run directus:provision`。

**升级提示（参考资料目录）**：新增 `reference_folders` 集合与 `reference_documents.folder_id` 字段，参考资料页改为项目内文件树，并新增资料 AI 批量扫描后台任务。Directus 模式下需要执行 `npm run directus:provision`；现有资料会自动保留在项目根目录。

**自动收尾规则**：用 `启动Kami工作台.cmd` 启动时（`KAMI_AUTO_SHUTDOWN=1`），真正关掉最后一个页面 15 秒后会停止工作台并退出 Docker Desktop；页面被最小化、切到后台标签等"挂机"状态不再算关闭——浏览器会把定时器节流到每分钟一次甚至冻结，只有心跳失联满 30 分钟才按关闭处理。后台任务（导入、清洗、批次翻译、导出）执行期间一律不自动收尾，任务结束再按上面的规则收尾。启动后如果一直没有任何页面报到（例如浏览器没打开），要等 5 分钟才收尾，避免浏览器冷启动慢一点就被误杀。三个宽限期分别用 `KAMI_AUTO_SHUTDOWN_CLOSE_GRACE_MS`（默认 15000）、`KAMI_AUTO_SHUTDOWN_HEARTBEAT_GRACE_MS`（默认 1800000）和 `KAMI_AUTO_SHUTDOWN_STARTUP_GRACE_MS`（默认 300000）调整。

**Directus 是唯一的生产存储，连不上就直接启动失败。** 这里曾经会静默回退到本地 JSON，代价比看起来大得多：回退后术语、翻译记忆、风格证据与学习轨迹都不在视野里，模型在零参考的情况下继续翻译，同时新写入落到 `data/` 形成数据分叉，界面横幅并不足以让人及时发现。现在 `KAMI_STORE=directus` 时启动探针失败会带上排查清单直接退出（Docker Desktop、`npm run directus:up`、`npm run directus:provision`、`directus/.env` 里的 `DIRECTUS_URL` 与 Service Token）。JSON 存储仍然保留，但只服务于单元测试。

默认模型地址是本地 Ollama 的 OpenAI-compatible 端点：

```text
Base URL: http://localhost:11434/v1
Model: qwen3:14b
```

可以在界面右上角“模型设置”中修改。Base URL、模型名称和 API Key 会保存在本机 `data/runtime/`；Key 使用 Windows 当前用户级 DPAPI 加密，不会以明文写入项目，也无法由其他 Windows 用户或复制到其他电脑后直接解密。该目录已加入 `.gitignore`。

Embedding 服务（语义向量检索用）可独立配置：模型名称、Base URL 与 API Key 三项单独设置，留空时回退到主模型配置。主模型 API 不支持 `/embeddings` 端点时（如 DeepSeek 官方 API），可把 Embedding 指向本地 Ollama（如 `nomic-embed-text`）或其他向量服务。

“模型设置”中还可以填写输入/输出价格（美元 / 百万 token）。两者都填写后，技能评测会自动启用真实成本门禁（按每次模型调用返回的 token 用量计费）；留空则成本门禁保持跳过，不会因为未计量而锁死晋升。对应的环境变量为 `LLM_INPUT_PRICE_PER_MTOK` 与 `LLM_OUTPUT_PRICE_PER_MTOK`。

环境变量优先于本地持久化配置，也可以使用：

```powershell
$env:LLM_BASE_URL='https://your-provider.example/v1'
$env:LLM_API_KEY='your-key'
$env:LLM_MODEL='your-model'
npm start
```

## 数据隔离

当前工作台只使用日语→简体中文的两张 PostgreSQL 表：

```text
terms_zh_cn
translation_memory_zh_cn
```

每次资产查询和翻译请求只能提交 `zh-CN`。后端通过固定白名单把它映射到唯一表名，不接受客户端指定任意集合；旧语言集合仅保留给历史数据读取，不会出现在工作台或新的写入流程中。`data/assets/*.json` 继续作为可读的初始迁移源和离线回退数据，不是 Directus 模式下的正式写入目标。

共享后台集合包括：

- `corpus_documents`：日语原始语料和切段结果
- `term_import_batches`：表格上传、清洗和入库批次
- `term_candidates`：日中术语候选、目标语言、评分、判断依据和处理状态
- `style_profiles`：简体中文与语体规则
- `style_evidence`：从双语长句提取的分类风格证据
- `qa_runs`：每次 AIQA 的检索证据、问题、分数与修订轨迹
- `qa_cases`：低分译文、修订译文和问题类型

## 批量术语导入

进入“术语导入”，拖入 `.xlsx` 或 `.csv` 即会自动开始结构识别，不需要补表头或再次点击开始。表格只需包含日语源列和简体中文目标列。系统会：

可直接复制 `samples/term-import-template.csv` 作为导入模板。

1. 由 AI 结合整列和成对行关系识别日语列、简体中文列、表头或无表头结构，并由后端校验真实列号。
2. 去除网址、纯数字、空值、重复对照和元数据；完整句子不再当术语，而是进入翻译记忆和风格证据。
3. 检查简体中文术语库中的已存在项及同源词译法冲突。
4. 在启用时调用模型做二次术语判断；模型不可用会自动回退本地规则。
5. 仅把人工勾选的候选写入日语→简体中文物理表。
6. 完整日中句段证据按项目跨批次累计（语体只用于分层取样）；达到阈值（默认 8 条）且通过蒸馏闸门后生成新的风格规范草稿，在术语库页对比新旧差异、跑配对评测并人工激活后生效。阈值与增长窗口分别由 `KAMI_STYLE_DISTILL_THRESHOLD` 和 `KAMI_STYLE_DISTILL_GROWTH_WINDOW` 调整。

候选日语和简体中文译法可以在审核表格中修改。自动判定为“需复核”的项目默认不勾选，“已存在”和“已排除”的项目不能直接导入。

### 双语资产导入（按去向分流）

「双语资产导入」页在拖入文件之前先选本次导入的类型，预检弹窗里可以最后调整：

- **术语表**：默认按表直接导入，不调用模型——本地规则把短词条写进术语库、完整句段写进主 TM；勾选「先做 AI 清洗」才逐条送模型判定（24 条/批、5 路并发，几千行会明显变慢）。
- **人工 TM**：整批作为人工确认译文写入主 TM，不调用模型；「作为风格学习证据」默认勾选，取消则只写主 TM。

确认后导入在后台执行：弹窗转为进度视图，可以直接关掉窗口继续下一步，进度与结果在任务中心可见。中断、失败或服务重启后，任务中心会给出「继续导入」，用同一批次续跑——已写入的原文+译文按重复跳过，所以续跑只会补齐剩余部分。导入完成会报告跳过条数与原因（已存在相同对照 / 库内已有译法 / 无效行）。

术语表的**注释列**（注释/备注/说明/備考/note/comment 等表头，无表头时由模型判定）会原样写进术语的 `note`，并在翻译时随强制/参考术语一起发给模型用于消歧；没有注释的术语 `note` 留空，批次与行号记账信息改记在 `provenance`（形如 `table-import:term_base.xlsx#4673`）。全新的空术语库导入 5859 行（关闭 AI 清洗）现在是秒级到一分钟级，不再需要等几分钟。

「记忆库 TM」页面的「导入人工 TM」支持一次选择多个文件，合并预检后一次写入，并可按页面上的勾选决定是否进入风格证据池。导入走**队列后置**：候选先留在本地预检缓存（`data/runtime/tm-preview`，7 天），主 TM 与风格证据写完之后才一次性写审计（`term_import_batches` + 精简候选行，直接写终态）；因此失败/中断时库里一行候选都不会留，任务中心的「继续导入」用同一个批次号从预检缓存重跑（记忆与证据按原文去重，不会写重），成功后才删除缓存。**同一项目重复导入同名文件时只留最新一批审计**：上一批 `tm-audit` 批次及其候选行会被批量删除（Directus `DELETE` + `{"keys":[…]}`，几万行一次请求），记忆与风格证据本来就是"命中即覆盖"，不会翻倍。

## 批次与文件翻译

进入“翻译”，切换到“批次 / 文件翻译”。可以直接粘贴长文，也可以上传 TXT、Markdown、DOCX、XLSX、CSV、XLIFF 或 MQXLIFF 文件。分段不使用固定字数：默认以一个完整句子作为翻译单元，也可以切换为一个自然段、Word 段落或 Excel 单元格作为翻译单元。

文件拖入后会自动解析，不需要手动添加或指定表头。对于 Excel，系统先发送列统计、部分行样本和规则建议给当前模型，识别正文、补充信息、约束、已有译文和忽略列；模型结论会经过后端列号和角色白名单校验。模型暂时不可用时自动回退到本地结构规则，并在界面明确标注“规则降级识别”。

系统先展示完整分段队列，不会直接开始翻译。启动批次时先对整份文档确定统一语体与基础风格，再为每个翻译单元携带上文、下文、文档位置、当前行的位置/备注、DDL/长度/语种约束、已有参考译文、当前简体中文术语匹配和风格配置。上下文只用于消歧与保持连贯，提示词明确禁止把补充信息或相邻内容混入当前译文。当前段完成后可以暂停，已完成进度会留在浏览器页面中。每段都会显示 QA 状态，失败项可以继续重试。导出时，未勾选或未完成的部分保留原文；DOCX 写回原段落，XLSX 只写回识别出的日语正文单元格，XLIFF/MQXLIFF 只写入原本为空且未锁定的目标单元并保留内联标签，TXT 与 Markdown 保留原换行结构。

## 持续学习与翻译技能

“学习中心”把每次翻译看成一条可追溯轨迹，而不是直接让模型改写自己的生产提示词。学习范围按 `日语→简体中文 × 项目` 结算：语体与领域由系统自动判定、只作参考（影响排序与提示词，不再隔离技能、资产与轨迹）。

- `learning_trajectories` 保存原文、初译、终译、使用过的术语/记忆/风格资产、AIQA 前后指标、人工决定、模型与提示词版本。
- `translation_skills` 保存版本化翻译策略。生产只读取当前 `champion`；模型复盘轨迹后生成的改进始终先成为 `challenger`。
- `skill_evaluations` 保存 Champion 与 Challenger 在独立人工终稿留出集上的逐项对比和晋升决定。

候选技能只能调整上下文范围、检索数量、风格指令与 QA 门槛等策略，不把某个偶然译法硬编码成通用规则。候选使用过的所有轨迹都会从留出集排除；至少积累 20 条独立、人工批准的终稿后，系统才会真正重跑新旧版本。强制术语正确率或硬错误发生退化时一票否决，QA、相对人工终稿的编辑距离、延迟等指标也必须满足门槛。只有评测结论允许晋升时，界面才开放人工批准；批准和回滚都保留完整版本链。学习存储暂时不可用时只会暂停沉淀，不会阻断正常翻译。

评测以**后台任务**运行：同一时刻只跑一个评测，界面实时显示逐对进度；每完成一对就落盘检查点（`data/learning/jobs/`），服务重启后任务标记为中断，可续跑剩余样本而不是从头重烧模型调用。评测前会剔除与留出原文同源的翻译记忆、QA 案例与风格/画像正反例，防止标准答案泄漏进评测上下文。

候选生成支持**自动提议**：同一作用域内人工批准的终稿达到阈值（默认 10 条，可用 `KAMI_AUTO_PROPOSE_THRESHOLD` / `KAMI_AUTO_PROPOSE_GROWTH_WINDOW` 调整）且当前没有待评测候选时，系统会在后台自动生成 challenger；评测与激活仍必须人工执行。自动提议的记账信息保存在 Champion 技能的 `metadata` 字段（Directus 模式下需运行 `npm run directus:provision` 创建该字段）。

风格规范走的是**另一条**评测线：`translation_skills` 评的是检索条数、附加指令与 QA 门槛等策略，`style_profiles` 评的是风格文本本身。在术语库页的风格草稿卡片上点“评测”，系统会用当前 champion 技能把草稿与当前生效版本跑同一组人工终稿留出集（至少 12 条，已剔除蒸馏时用过的原文及其去标点同形变体），只让风格规范这一个变量变化。

评测有两条不可省的规矩：AIQA 会读风格规范当作 nuance 尺子，所以两侧一律用**当前生效版本**打分，否则草稿等于自己给自己判卷；相应地，QA 分与合成接受率只保留“不得下降”的护栏作用，能作为晋升理由的只有与人工终稿的编辑距离、强制术语正确率和硬错误数——这三项不受风格规范影响。评测结论写在草稿的 `evaluation` 字段上；结论反对时激活返回 409，确需启用要显式忽略结论，届时 `activationBasis` 会记为 `forced`，未评测直接启用记为 `unevaluated`。

四份提示词素材会**互相检查**。人工风格指南、蒸馏规范、技能附加规则（生效版本 + 全部候选）与译者画像都往同一份翻译提示词里写文字，彼此并不知情：技能可能带着“句尾用简体”晋升，而风格规范写着“句尾统一敬体”，模型只会挑一条照做，配对评测也只能间接察觉（编辑距离变差）。「风格指导」页的“规则冲突审查”按**项目**把这四方规则拉平成同一形状后逐对比较，优先级固定为**人工指南 > 蒸馏规范 > 技能规则 > 译者画像**：与人工指南冲突的蒸馏规则可以一键退休，未生效的候选技能可以一键停用，生效版本只出结论（走回滚或新候选）。先用确定性预筛把只谈不同方面的组合剔掉（避免让模型在 O(n²) 对里瞎猜），再把剩下的至多 12 对交模型裁决。判为矛盾的门槛很窄：必须能指出一个**同时遵守两条就不可能**的具体场景；总则与例外（“统一敬体”与“战斗吼叫用常体”）、适用场景不同、要求不同但可共存的，一律不算。模型不可用时只报“模型不可用”，绝不把预筛候选当成结论——预筛是刻意放宽的，直接上报会全是误报。

## 发版门禁与失败回归

晋升候选技能前，必须在这套不随人工终稿漂移的固定资产上真跑一遍：固定 Gold Set（`quality_assets` 里的 `gold_set`）与失败回归集（`regression_suite`）。回归案例一票否决，Gold 术语或事实退化同样阻断发版。

回归案例不再依赖有人在工作台里逐条复核 QA，而是从**外部审校回填**里自动派生：回填时人工把机器稿改成了什么，就是“候选不允许再犯”的名单。`src/regression-sources.mjs` 按归一化编辑距离（默认 0.2，见设置项「审校改动入回归集阈值」）筛出真正的错译，机器稿优先取轨迹里的 `humanDecision.machineTranslation`，旧数据回退到批次段落记录的 `previousTranslation`；内容没变就复用现版本，变了才自动出新的回归集版本。人工采纳过的 QA 失败案例仍然可以并入，但同样不需要第二次审批与署名。

回填或新候选生成后会自动触发一次门禁（没有候选就跳过，不空跑生效版本），单次按改动幅度最多跑 50 条回归案例。门禁结论与资产版本绑定：Gold Set 或回归集出了新版本，旧 `pass` 自动作废，需要重跑；`POST /api/learning/skills/:id/activate` 不再接受人工署名放行。

门禁失败不是死路：面板上的「总结失败原因」会把复发的失败按根因归类（术语 / 体例 / 事实锚点），每条给出原因与可执行建议。术语类可以一键「提为术语候选」（走下面同一套入库策略），体例类可以一键「据此生成新候选技能」——它把复盘报告与失败原文、人工终稿一起交给模型产出策略补丁，之后仍走原有的净化、评测与门禁链路，只是证据从轨迹换成了失败案例。同一批待测清单按原文去重（`learning.gateDedupeSources`），Gold 与回归重叠的原文只翻一次、同时按两套规则判定。

## 翻译期术语发现与自动入库

整批翻完后会自动跑一次术语普查（`learning.termSurveyEnabled`）：模型逐片看「原文 + 机器译文」，指出应该作为术语管理但库里没有的专名、固定 UI 用词与必须原文照抄的标识，结果连同依据一起挂在批次记录上。

人工审校稿回填时，才由**人工终稿**决定译法：AI 建议的译法在终稿里逐字保留 → 直接采纳；被人工改掉 → 让模型在终稿里找实际写法，找不到就转待审核；回填段落里没出现的源词直接忽略。入库分两档（`learning.termAutoWriteReviewedTerms`）：只有「库里没有该源词 + 终稿逐字保留了 AI 建议译法 + 形态合规」才自动写入项目术语库（写进优先级最高的启用术语库，并在任务行写明库名）；模型推断、与库里冲突、形态超长的一律进待审批次，在任务中心显示「术语候选待审核」，到双语资产导入页批量确认后才入库。自动入库不回溯修改历史 TM，新术语从下一次翻译开始生效。

裁决为真之后按证据强弱衡量：风格规则按累计证据数加轮次计权，技能规则没有证据计数（它靠配对评测晋升）因而折算成相当于 50 条证据的中等权重，势均力敌则交人工。**只有输的那条是风格规则时**才会给出“退休这条风格规则”的按钮，点了立刻退出提示词并留下退休原因；输的是技能规则或译者画像时一律只报告不动手——技能须经 challenger 评测晋升，画像须走草稿流程，扫描不能代劳。

扫描在两个时机触发：蒸馏**真的产出新草稿**之后自动扫一遍（规则集刚变过才值得扫；人工采纳本身不改规则，在那里扫是白烧模型调用），以及按 `learning.conflictScanIntervalMinutes` 定时扫（默认 0，即只在沉淀后扫）。并发触发会被串行化，扫描自身永不抛出。规则化之前的存量规范只有整段散文、没有可逐条比对的单位，报告会直接说明这一点，下次蒸馏拆成规则后自动纳入。

模型返回的策略补丁是不可信输入：入库前经过白名单校验与净化——未知区块和字段丢弃、数值按区间夹紧、规则与指令长度截断、控制字符剥离，并拦截"忽略以上规则"类中英文注入特征；净化明细记录在候选的 `metadata.sanitization` 并在学习中心展示。

## 当前原型边界

- 旧版 `.xls` 需先另存为 `.xlsx`；JSON、YAML、PO 和游戏资源包尚未接入结构化回写。XLIFF 仅支持 1.2 格式及 `.xliff` / `.mqxliff` 扩展名。
- DOCX 会保留文档容器、段落和非文本对象，但一个段落内部跨多个样式 Run 的文字在写回时会合并到首个 Run；复杂排版文档仍建议导出后人工检查。
- 模型不可用时仍会使用本地整列规则推断；纯汉字日文、极短样本及高度相似的简繁列仅靠规则存在歧义，应在预览中确认日语源列与简体中文目标列。
- 当前 AI 只负责候选保留/排除判断，不会擅自改写原表中的日中术语。
- 智能术语当前结合编辑距离、字符重排、别名和模型译文对齐；完全没有词面关联的同义概念仍建议补充别名。
- 模型质量取决于接入的模型和为日语→简体中文积累的正式资产。

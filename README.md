# Kami DSH

基于 [xiaoxinblast/kami](https://github.com/xiaoxinblast/kami) 的本地日语→简体中文翻译工作台，以 DSH 插件和专用 agent 预设运行。

DSH Agent 查阅工作区原文件，Kami 执行批量翻译、QA、续跑与原格式导出。人工审校在 memoQ 完成，再用本地双语终稿更新翻译记忆、学习轨迹和术语。项目与资产数据存入 SQLite，模型复用 DSH 会话配置。

## 安装与更新

支持 DSH `0.2.1-rc.2` 至 `0.2.1-rc.5`，以及 `0.2.2-rc.1`、`0.2.2-rc.2`。升级到 DSH `0.2.2-rc.2` 后，请使用 Kami `0.9.35` 或更高的兼容版本。

1. 在 DSH 的“插件”→“添加插件”中填写 `https://github.com/xiaoxinblast/kami-dsh#main`。
2. 打开工作区会话，选择“Kami 翻译工作台”预设，在右侧工作台明确绑定已有项目或新建项目。
3. 选择 DSH 会话模型，在主会话中委托翻译，或使用工作台“任务”中的“快捷建批”。

GitHub 安装不会自动更新。已注册 `dsh` 命令的桌面 profile 可执行：

```powershell
dsh plugin --profile desktop update kami-dsh --latest
```

也可通过插件管理页重新安装仓库地址。更新后按管理结果正常重启 DSH，并新建 Kami 会话以加载新版预设；本地资产保存在独立数据目录。CLI 路径、固定版本安装与故障处理见 [DSH 使用说明](docs/DSH.md#安装)。

## memoQ 翻译流程

1. **准备原文**：从 memoQ 导出双语 MQXLIFF / XLIFF，放在当前 DSH 工作区。
2. **关联资产**：进入“资产”，按库关联本地术语、TM、风格指南和参考资料；术语和 TM 关联后自动交给当前 Agent 理解原文件并编译，显示“已编译，可用于翻译”后用于翻译。风格指南只关联原文件，翻译和审校前由 Agent 使用会话工具直接读取并遵守，不预解析或生成文字编译副本。启用所需库，用 ↑ / ↓ 调整术语库和 TM 库的优先级。
3. **翻译与机检**：让 Agent 关联待译文件、查阅资源、预览原文并创建批次，再执行翻译和 QA。任务可暂停、续跑。
4. **导出初稿**：在“工作区导出”中按原格式写入工作区，默认目录为 `outputs/`。导出不覆盖原件或已有同名文件。
5. **在 memoQ 审校**：将译稿导回 memoQ，逐段人工审校；完成后把双语终稿导出到工作区。
6. **关联人工终稿**：进入原任务的“终稿与学习”，填写终稿相对路径，选择已启用的主 TM 或参考 TM，完成一次关联。无需在 Kami 中逐段采纳。

关联终稿后，会核验原文与条目身份，并报告结果：

- **TM**：有效对齐的终稿译对进入目标库；原文件中已有译文或锁定的有效条目也可保留。
- **学习轨迹**：唯一对齐到当前批次的译段连接 AI 初稿与人工终稿，保留首次机器稿和上一版终稿。无法对齐的条目不生成学习轨迹。
- **术语**：以人工终稿为依据更新术语普查；证据充分的新译法可写入，已有译法冲突、禁用词或证据不足的条目保留待核对。

重复关联同一已完成版本会复用结果；终稿更新后可再次关联。在“学习”页可从人工终稿生成项目风格候选，完成评测和门禁检查后，由用户激活。普通 TM 文件关联仅提供参考，不会自动成为人工终稿或学习规范。

## 本地文件与资产

“资产”统一管理术语库、记忆库 TM、风格指南和参考资料。术语/TM 以“库 → 关联本地文件 / 已有条目”为入口，支持文件浏览、搜索与版本查看。

- 只关联工作区原文件，不需要上传、导入或另存纯文本副本；关联入口不沿用服务器的文件大小与扩展名限制。Agent 使用已配置的工具查阅原文件，无法读取时报告具体问题。
- 路径相对当前工作区，关联和解除关联均保留原件。配置记录在 `.kami/project.json`。
- 术语和 TM 由 Agent 识别原文件结构，再编译为可注入资源，不要求原件采用固定模板。文件列表可勾选文件或文件夹、跨页全选并“编译选中”；“编译全部待编译”处理已启用资源。每个库只有一份统一编译文件；只增量更新所选来源，保留其他内容，并合并重复句对的来源和备注。原件未变化时跳过；后续建批自动加载，不自动写入正式资产库。
- 文件名旁显示“已完成编译”或“待编译”气泡；文件夹汇总所有子文件，显示完成状态及已完成数/总数。原件变化后状态自动更新，读取失败单独提示。
- 参考资料只关联原件，不预解析、分块或编译。翻译与审校时，Agent 按需使用当前 DSH 会话的文件、搜索、识图及文档技能直接查阅；正文以实际读取的原件为准。
- 术语库和 TM 库的优先级数字越小越优先，关联文件沿用所属库的启停状态。调整后用于新批次，已有批次继续使用冻结的资源版本。
- 建批时冻结原文及术语、TM 版本；后续续跑、QA 与导出使用同一快照。风格指南和参考资料只记录关联信息，正文以实际读取时的当前原件为准。旧批次保留原来的风格指南快照；要使用原件查阅流程需新建批次。

待译文件的分段和原格式写回支持 TXT、Markdown、DOCX、XLSX、CSV、XLIFF、MQXLIFF；资源原文件由 Agent 按工具能力查阅。详细配置与 Agent 示例见 [工作区配置与文件引用](docs/DSH.md#工作区配置与文件引用)。

## 翻译强度

自动模式逐段判档，也可手动指定：

| 档位 | 自动选择条件 | 执行方式 |
| --- | --- | --- |
| 快速 | 不超过 80 字的低风险 UI / 名称，无事实锚点、术语冲突或交付约束，保护标记不超过 2 个 | 单次生成与规则检查 |
| 标准 | 未触发严苛条件的其余句段，包括对白、叙述与普通长文 | 初译与模型 QA，有问题才修订，最多一轮 |
| 严苛 | 承诺或法务措辞、至少 2 个术语冲突、至少 2 项交付约束，或公告/规则中的至少 2 项事实锚点 | 一份初译与一次加强模型 QA，有问题才定向修订，修订后只做规则检查 |

长度或两个数字本身不单独触发严苛档。默认严苛流程不叠加多候选和独立反思；快速档规则检查失败时可升档复用现有译文，已完成模型 QA 的句段不再自动升档重审。模型 QA 失败会保留未完成状态。档位调整的是处理流程，实际模型沿用 DSH 会话配置。

逐段 QA、QA 修订及重试 QA 均接入原文件查阅：必须成功读取关联的人工风格指南，参考资料按需读取。同一段本轮 QA 的工具证据在 QA 与修订间复用，不生成正文缓存文件，也不跨段或跨次重试复用；重新发起 QA 时重新读取当前原件。自动流程为“初译 → 一次模型 QA → 必要时修订 → 本地规则检查 → 结束”，取消修订后的模型复检；整批一致性检查保留。修订后的状态为“已修订”，最终模型分数留空，修订前的问题和分数保存在 QA 案例中，不将修订稿写为机器已验证译例。已有译例时不重复计算 QA 检索向量；修订未改变译文时保留原 QA 结论，停止自动升档重复调用。

重试 QA 只补查未完成的 QA、保存结果后结束，不再触发一致性检查和术语普查，也不使已有报告与普查结果过期。正常整批翻译（含补跑翻译）结束后，仍按自动开关依次执行一致性检查和术语普查。

## 本地数据与开发验证

日常运行在 DSH Host 内执行，不需要独立 Kami 后端、Directus 或 Docker。数据位于 `$DSH_HOME/kami-dsh/<profile>/`，默认桌面 profile 为 `desktop`；SQLite 保存项目、资产、任务和学习记录，运行目录保留任务原件快照。

本地开发要求 Node.js `>=24.2`：

```powershell
npm ci
npm run dsh:check
npm test
npm pack --dry-run
```

测试中有环境条件的项目可能跳过，跳过不计作验证通过。安装、旧资产迁移、完整备份与验收记录见 [DSH 使用说明](docs/DSH.md)。

本项目保留 Kami 的历史与业务代码。上游服务版说明保存在 [原版说明](docs/KAMI-UPSTREAM.md)。
